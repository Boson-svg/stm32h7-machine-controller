## 二、DMA2D 配置与理解

### 2.1 当前配置

| 配置项 | 当前值 | 作用 |
|---|---|---|
| Activation Status | Activated | 启用 DMA2D |
| Runtime Core | Cortex-M7 | 由 CM7 使用 |
| Power Domain | D1 | DMA2D 所在电源域 |
| Transfer Mode | Memory to Memory | 内存到内存传输 |
| Color Mode | RGB565 | 与 LTDC 和屏幕像素格式一致 |
| Output Offset | 0 | 连续填充时每行不额外跳过像素 |
| Foreground Input Color Mode | RGB565 | 前景输入数据格式 |
| Alpha Mode | No modification | 不修改 Alpha 通道 |
| Input Alpha | 0 | 当前 RGB565 模式下不作为透明度处理 |
| Input Offset | 0 | 输入区域无额外行偏移 |
| Alpha Inversion | Regular Alpha | 保持正常 Alpha 解释 |
| Red/Blue Swap | Regular mode | 不交换红蓝通道 |
| Chroma Sub-Sampling | 4:4:4 | 不进行色度抽样 |

### 2.2 清屏工作链路

```text
ltdc_clear(color)
        │
        ▼
设置 DMA2D 输出颜色、目标地址、宽高
        │
        ▼
DMA2D 将颜色写入 SDRAM 帧缓冲
        │
        ▼
LTDC 自动从帧缓冲读取像素并刷新屏幕
```

清屏使用 DMA2D 的硬件填充能力，替代 CPU 手写双重 `for` 循环。DMA2D 的矩形大小、目标地址和颜色属于运行时参数，不是全部固定在 CubeMX 初始化中。

### 2.3 DMA2D 相关踩坑

1. DMA2D 的像素格式必须与 LTDC 和帧缓冲格式一致，当前统一使用 RGB565。
2. 不能直接复用原项目的 ARGB8888 颜色宏；当前使用 RGB565 颜色值，例如 `RED = 0xF800`。
3. 全局 LCD 参数必须先由 `ltdc_param_init()` 初始化，否则宽高为 0 时可能发生无符号下溢，产生越界填充。
4. 正式版本还需要补充 DMA2D 忙状态和超时处理。

## 三、正式 LCD 驱动

当前 LCD 模块位于 `BSP/LCD/`，主要接口如下：

```text
ltdc_gpio_init()   屏幕供电、复位、背光 GPIO 初始化
ltdc_param_init()  宽高、方向、像素格式、帧缓冲参数初始化
ltdc_fill()        填充指定矩形区域
ltdc_clear()       使用 DMA2D 清屏
```

屏幕控制引脚与 LTDC 外设引脚分开：

| 引脚 | 功能 |
|---|---|
| PI11 | 屏幕供电 |
| PH5 | 屏幕复位 |
| PB0 | 背光 |

上电顺序为：

```text
供电打开 → 复位脉冲 → 等待屏幕稳定 → 背光打开
```

LTDC 高速 RGB 引脚的 GPIO Speed 已配置为 `VERY_HIGH`。本项目中曾出现屏幕纯黑，最终通过对比 CubeMX 生成代码和原项目配置，确认 GPIO 速度过低是根因之一。

## 五、FT5446U 触摸驱动理解

### 5.1 型号与驱动文件名

实际触摸控制器是 FT5446U，工程文件仍命名为 `ft5206.c`。原因是 FT5446U 与 FT5x06 系列在基础 I2C 寄存器协议和坐标数据格式上具有兼容性。

当前驱动能够完成基础功能，但不能因此认为已经覆盖 FT5446U 的全部能力。当前数组和扫描条件最多处理 5 个点，而芯片资料标称支持更多触摸点。

### 5.2 初始化寄存器

当前代码实际写入关系如下：

| 目标寄存器 | 写入数据 | 当前含义 |
|---:|---:|---|
| `0x00` | `0x00` | Device Mode 设置为正常工作模式 |
| `0xA4` | `0x00` | 使用轮询方式，匹配当前 `ft5206_scan()` 设计 |
| `0x80` | `0x16` | 触摸检测阈值参数，属于当前驱动配置值 |
| `0x88` | `0x0C` | Active 状态周期参数 |

这里必须区分“寄存器地址”和“写入数据”：

```c
ft5206_wr_reg(寄存器地址, 数据缓冲区, 数据长度);
```

例如：

```text
0x80 ← 0x16
```

不是把 `0x80` 写入芯片，而是向地址为 `0x80` 的寄存器写入 `0x16`。

### 5.3 触摸点寄存器布局

```text
0x02：触摸点数量
0x03：第 1 个触摸点
0x09：第 2 个触摸点
0x0F：第 3 个触摸点
0x15：第 4 个触摸点
0x1B：第 5 个触摸点
```

每个触摸点占 6 个字节：

```text
字节 0：事件类型 + X 坐标高 4 位
字节 1：X 坐标低 8 位
字节 2：触摸 ID + Y 坐标高 4 位
字节 3：Y 坐标低 8 位
字节 4：压力或权重相关信息
字节 5：其他信息
```

当前代码读取每个触摸点的前 4 个字节，暂时不处理压力和其他信息。

### 5.4 坐标解析

```c
raw_x = ((buf[0] & 0x0F) << 8) | buf[1];
raw_y = ((buf[2] & 0x0F) << 8) | buf[3];
```

根据屏幕安装方向，代码会交换 X/Y 或反转坐标，将触摸芯片原始坐标转换为 LCD 屏幕坐标。

### 5.5 触摸状态验证

通过调试解析代码观察 `buf[0]` 的事件字段，并结合触摸点数量变化，已验证：

```text
手指按下：能够识别
手指移动：能够识别
手指抬起：能够识别
触摸释放：不会持续输出旧坐标
```

原始事件字段通常位于 `buf[0]` 的 bit[7:6]：

```text
00：按下
01：抬起
10：接触/移动
11：保留
```

需要注意：当前扫描逻辑在触摸点数量为 0 时主要通过状态变化推断释放，不一定会读取到最后一个原始抬起数据包。

## 六、软件 I2C 理解与验证

软件 I2C 使用 GPIO 位操作模拟总线，已理解并验证以下基础时序：

```text
起始条件：SCL 高电平期间，SDA 由高变低
停止条件：SCL 高电平期间，SDA 由低变高
发送数据：SCL 低电平时改变 SDA，SCL 高电平时保持稳定
读取数据：释放 SDA，SCL 拉高后采样
```

SDA 使用开漏输出：

```text
写 0：MCU 主动拉低 SDA
写 1：MCU 释放 SDA，由上拉电阻拉高
```

当前软件 I2C 能够正常读取 FT5446U 的设备信息和触摸坐标，说明总线通信链路已在板上验证通过。

## 七、当日踩坑与方法论

### 7.1 DMA2D 和显示

1. DMA2D 配置参数多，但清屏时真正关键的是传输模式、像素格式、目标地址、颜色、宽高和行偏移。
2. RGB565 屏幕不能直接使用 ARGB8888 颜色宏。
3. LCD 全局宽高必须先初始化，否则可能出现越界填充。
4. LTDC 高速引脚必须使用 `VERY_HIGH` GPIO Speed。

### 7.2 软件 I2C

1. `for (i = 0; i < 0; i++)` 会导致发送循环一次都不执行，正确上限是 8。
2. SCL 高电平期间 SDA 必须稳定。
3. SDA 必须使用开漏输出，写 1 的含义是释放总线。
4. 软件 I2C 的微秒延时是忙等待，后续接入 FreeRTOS 时不能直接替换为 `osDelay()`。

### 7.3 工程组织

1. 头文件只放全局变量声明，使用 `extern`；变量实体在 `.c` 文件中定义。
2. 使用 `printf` 的源文件必须包含 `<stdio.h>`。
3. 新建 `.c` 文件必须加入 Makefile 的 `C_SOURCES`，否则文件不会参与编译。
4. CubeMX 生成代码时，自定义调用和 include 应放入 `USER CODE` 区域。
5. 驱动移植必须先理解模块职责，再加入工程，不能只复制文件而跳过接口和验证。
